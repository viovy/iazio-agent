## 1. Design System Token & Accessibility Audit

### 1.1 Semantic Color Token Compliance
In [iazio-web/lib/screens/repo_detail_screen.dart](file:///Users/romeo/work/meta-repo-02/iazio-web/lib/screens/repo_detail_screen.dart#L1347-L1410), the remediation refines the rendering condition for the halted worktree error card without altering its design token bindings:
- **Card Background**: `Theme.of(context).colorScheme.errorContainer`
- **Text & Content**: `Theme.of(context).colorScheme.onErrorContainer`
- **Icon**: `Icons.warning_amber_rounded` with `Theme.of(context).colorScheme.error`
- **Inner Metadata Container**: `Theme.of(context).colorScheme.surface` with border `Theme.of(context).colorScheme.outlineVariant`
- Zero hardcoded RGB/HEX color literals are introduced. All colors derive strictly from Flutter Material 3 `ColorScheme` tokens.

### 1.2 WCAG 2.1 AA Contrast & Accessibility
- **Contrast Ratios**: The pairing of `errorContainer` and `onErrorContainer` is defined by Material 3 specification to maintain a contrast ratio >= 4.5:1 for body and title text across both light and dark themes.
- **Non-Color Indicators**: Warning status is communicated through both semantic color and an explicit iconography cue (`Icons.warning_amber_rounded`), complying with WCAG 1.4.1 (Use of Color).
- **Screen Reader Hierarchy**: Text content uses a bold title followed by explanatory body text, allowing assistive technologies to navigate header and detail hierarchy cleanly.
- **Zero Critical/Serious Violations**: No layout clipping, overflow exceptions, or touch target violations exist in the guarded block.

### 1.3 Responsive Layout & State Transitions
- The card is wrapped in flexible layout containers (`Row`, `Expanded`, `Column`), ensuring clean reflow across narrow mobile and wide desktop viewports.
- The guard logic:
  ```dart
  else if ((repo.reason == 'HALTED_DETACHED' || repo.hasFleetDirtyState) &&
      repo.lock != HarnessLockState.runningHarness &&
      repo.lock != 'RUNNING_HARNESS' &&
      job == null)
  ```
  prevents card layout thrashing by cleanly toggling between the active harness running card and the halted card based on authoritative lock state.
