## 1. UX Problem Statement & Operator Friction Analysis

Prior to this fix, an operator inspecting a multi-slot host (such as `debian` running co-located slots `/home/romeo/work/meta-repo` and `/home/romeo/work/meta-repo-02`) encountered severe cognitive friction and conflicting UI states:

1. **Copy-State Contradiction ("Schrödinger's Job")**:
   - The repository screen displayed both `Harness Executing Prompt` (`Lock: RUNNING_HARNESS`) and a high-urgency red card: `Worktree Uncommitted Changes / Job scheduling is halted on this worktree`.
   - Operators were forced to guess whether the agent was actively executing or stalled/blocked.
2. **Ghost Attribution Across Sibling Slots**:
   - Both `/home/romeo/work/meta-repo` and `/home/romeo/work/meta-repo-02` displayed the same active job ID (`job_5caae91005a69cef`).
   - Operators could not distinguish which directory was actually modified without SSHing into the host and manually inspecting process tables.
3. **Hazardous Operator Remediation Prompts**:
   - The red halted card rendered a prominent "Resume in Place" / remediation action. If clicked while an autonomous agent was mid-turn, concurrent git commands risked corrupting the agent's worktree.

## 2. Product Interaction & UX Design Verification

### 2.1 Error Banner Suppression & Information Hierarchy
- **Card Demotion**: In [iazio-web/lib/screens/repo_detail_screen.dart](file:///Users/romeo/work/meta-repo-02/iazio-web/lib/screens/repo_detail_screen.dart#L1344-L1350), the red halted card is suppressed when `repo.lock == HarnessLockState.runningHarness`, `repo.lock == 'RUNNING_HARNESS'`, or `job != null`.
- **Truthful Status Preservation**: The header status chips (`Git Status: N modified files`, porcelain line items, branch chips) remain visible. The UI truthfully reflects that files are actively changing without mischaracterizing normal progress as a system failure.
- **Widget Test Verification**: [iazio-web/test/widget/agent_resilience_and_fleet_status_test.dart:RepoDetailScreen suppresses Worktree Uncommitted Changes halt card while RUNNING_HARNESS is active](file:///Users/romeo/work/meta-repo-02/iazio-web/test/widget/agent_resilience_and_fleet_status_test.dart#L493-L526) confirms the red error card is absent while `Harness Executing Prompt` and `Git Status: 2 modified files` are rendered.

### 2.2 Deterministic Multi-Slot Hierarchy
- **Single-Slot Clarity**: `BindDispatchJobRepo` and `findActiveDispatchJobForRepo` ensure that an active job is attributed to exactly one worktree slot on the host. Sibling slots immediately revert to `Lock: IDLE` and `Queue: OPEN`.
- **Cognitive Load Reduction**: Operators can see at a glance exactly which slot is occupied, what branch is being worked on, and which slots remain available for new queue allocations.

### 2.3 Post-Job Failure Flow
- If a job fails or exits dirty without landing, the control plane transitions the worktree to `ASEState: FAILED_DIRTY` and `Queue: PAUSED`.
- At this point (when `repo.lock` returns to `IDLE`), the red `Worktree Uncommitted Changes` card legitimately reappears with the `Resume in Place` button, providing safe, timely recovery tools exactly when needed.
