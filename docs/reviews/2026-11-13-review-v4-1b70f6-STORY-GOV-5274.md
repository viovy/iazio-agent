## 1. Autonomous Hardening & Automation Resilience

### 1.1 Zero-Prompt Headless Execution
- All changes across `iazio-agent`, `iazio-harness-api`, and `iazio-web` execute strictly in non-interactive mode.
- In [iazio-agent/internal/supervisor/execution_detector.go](file:///Users/romeo/work/meta-repo-02/iazio-agent/internal/supervisor/execution_detector.go#L295-L398), path-boundary scanning is completely deterministic and in-memory, requiring zero external terminal prompts, child process probing, or interactive confirmation.
- In [iazio-agent/internal/worker/dispatcher.go](file:///Users/romeo/work/meta-repo-02/iazio-agent/internal/worker/dispatcher.go#L1335-L1345), `ackLeaseWithWorktree` performs asynchronous RPC lease updates under context cancellation, preventing headless runner hangs.

### 1.2 Layer 3 Auto-Remediation & Self-Healing
- **Stale Dirty Pause Auto-Clear**: In [iazio-harness-api/internal/control/engine.go:BindDispatchJobRepo](file:///Users/romeo/work/meta-repo-02/iazio-harness-api/internal/control/engine.go#L2209-L2212), when an autonomous runner binds to a designated worktree slot, any stale pause state caused by previous runs (`ReasonDirty`, `ReasonAdhocASE`, `ReasonDetached`) is cleared automatically (`Queue = QueueOpen`, `Reason = ""`). This prevents runners from getting trapped in deadlocked paused queues without requiring operator intervention.
- **Phantom Lock Scrubbing**: In [iazio-harness-api/internal/httpserver/server.go:enrichRepoWithDispatch](file:///Users/romeo/work/meta-repo-02/iazio-harness-api/internal/httpserver/server.go#L3740-L3746), repository locks referencing non-existent or terminated jobs (`job_<hex>`) are automatically reset to `LockIdle`, self-healing stale locks following host restarts or transient network partitions.
- **Sibling Repo Lock Eviction**: In both `BindDispatchJobRepo` and `HeartbeatWithCapabilities`, when a job confirms binding to a specific slot, sibling slots holding the same job ID are automatically released, guaranteeing mutual exclusion across parallel worktree slots.

### 1.3 Transactional FSM & Telemetry Propagation
- Control plane state mutations in `engine.go` execute under mutex locks (`e.mu.Lock()`) and trigger asynchronous notifications (`notifyRepoLocked`) to ensure WebSocket subscribers and telemetry streams reflect true state transitions without race conditions.
- `UpdateRuntimeMetadata` updates both `job.Repo` and `job.WorktreePath` inside the queue's internal lock, preventing inconsistent metadata exposure to schedulers.
